# 故事驱动词汇学习设计

## 目标

把“通过故事背单词”恢复为每次学习任务的主线。学生先在一段有情节、有因果关系的原创中文故事中遇见 6 个英文目标词，再通过故事情节回忆、词义测试和拼写测试完成学习。学生应当能借助人物、冲突和结果回想单词，减少孤立记忆的痛苦。

## 用户体验

学习流程固定为四步：

1. 故事阅读：显示标题、情节进度和 3 个短段落。英文目标词自然嵌入中文叙事并醒目标记。
2. 情节回忆：逐题显示故事中的情境线索，学生从本故事的英文词中选择填回情节。
3. 词义测试：沿用现有词义选择题和逐题反馈。
4. 拼写测试：沿用现有规则，只测试标记为需要拼写的词。

点击故事中的英文词，页面在当前故事卡内显示拼写、音标、中文核心义和该词在本故事中的用法。学生可以点击“播放发音”；浏览器不支持语音时，音标和文字信息仍然可用。词义卡不得遮住继续阅读和下一步按钮。

故事阅读和情节回忆只代表接触与练习，不计作掌握。老师、家长和学生报告继续只使用真实词义、拼写、复习和有效学习时长记录。

## 内容规则

- 26 个 List 各提供 1 个原创故事单元，每个单元使用该 List 中 6 个词。
- 每个故事包含标题、简短引子、3 个段落和 6 条情节回忆提示。
- 每个目标词至少在故事正文中出现一次，并有唯一的情节回忆提示和具体用法说明。
- 故事应适合中学生阅读，情节清楚、有一个问题和一个结果；避免血腥、色情、歧视和需要成人背景知识才能理解的内容。
- 不复制参考 PDF 的原文、人物、标题或插图，只学习“连续故事承载目标词、即时释义、故事后复习”的方法。
- 单词选择以能自然进入同一情节为先，不强制取词表前 6 个。
- 中文释义以现有 `src/data/vocab.ts` 为唯一词库来源，故事数据只保存情境用法，不复制或改写标准释义。

## 数据与接口

新增独立故事数据层：

```ts
export type StorySegment =
  | { type: "text"; text: string }
  | { type: "word"; wordId: string };

export interface StoryParagraph {
  id: string;
  segments: readonly StorySegment[];
}

export interface StoryRecallPrompt {
  wordId: string;
  cue: string;
}

export interface StoryUnit {
  listId: ListId;
  title: string;
  hook: string;
  paragraphs: readonly StoryParagraph[];
  usageNotes: Readonly<Record<string, string>>;
  recallPrompts: readonly StoryRecallPrompt[];
}

export function getStoryUnit(listId: ListId): StoryUnit;
export function getStoryWordIds(unit: StoryUnit): string[];
export function storyRecallChoices(unit: StoryUnit, wordId: string): string[];
```

正文使用结构化片段，由 DOM API 创建节点，不使用 `innerHTML`。故事数据不进入本地学习档案，因此保持 `SCHEMA_VERSION = 1`，已有中断恢复记录继续使用内部步骤名 `study`。

## 界面边界

本次只优化学习卡内部：故事阅读版式、目标词标记、词义详情、步骤进度和情节回忆。首页、计划创建、三类报告的信息架构和全站视觉风格不重做；老师和家长报告不新增故事正文或故事阅读明细。

旧原型页面中被新应用覆盖的内容从主入口移除，使页面只保留一个可访问的应用根节点，避免屏幕阅读器读到两套界面。旧原型不参与真实学习流。

## 状态与恢复

- 进入故事页时保存 `step: "study"` 和故事的 6 个 `wordIds`。
- 进入情节回忆时保存 `step: "recall"`；刷新后从情节回忆首页重新开始，不保存单题进度。
- 进入词义或拼写测试时继续使用现有检查点。
- 复习任务也从同一故事开始，以情节作为回忆线索。

## 可访问性与响应式要求

- 所有目标词和选项均可用键盘操作，并有可见焦点。
- 目标词按钮使用 `aria-expanded` 表达详情开合状态；学习步骤使用文字，不依赖颜色区分。
- 360px 宽度下不横向滚动，按钮触控高度至少 44px。
- 桌面宽度下故事卡最大宽度不超过 760px，正文行宽适合连续阅读。

## 验收标准

- 从任一 List 开始任务，都先进入对应故事，且后续四步使用同一组 6 个词。
- 点击任意目标词能看到正确音标、词义和故事用法，并可触发浏览器发音。
- 6 道情节回忆题均来自刚读过的故事；未完成当前题不能进入下一题，作答后立即显示正确答案。
- 情节回忆结束后进入现有词义测试，之后按既有规则进入拼写测试并保存真实记录。
- 刷新后可以从 `study`、`recall`、`meaning` 或 `spelling` 对应步骤恢复。
- 故事数据完整性测试覆盖 26 个 List、词 ID、正文出现、用法说明和回忆提示的一一对应。
- 既有测试全部通过，类型检查和生产构建通过；在手机与桌面视口完成视觉和易用性检查。

## 本轮不做

- 不重新设计首页、计划页或报告页。
- 不把故事阅读次数或故事内容加入老师、家长报告。
- 不增加登录、云同步、班级管理、支付或会员购买流程。
- 不复制参考资料中的文字、人物或图片。
