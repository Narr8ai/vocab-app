# Vocab App 第一阶段产品设计

## 目标

把现有 GitHub Pages 演示页改造成无需登录、可在单台设备持续使用的词汇学习工具。第一阶段继续使用现有演示词库，重点验证“计划、学习、测试、错题、复习、报告”是否形成真实数据闭环。

## 范围

第一阶段保留现有视觉风格、26 个 List 的产品结构和 GitHub Pages 在线访问方式。保留学生、家长、老师三种报告视角，但它们只是同一用户数据的三种阅读方式，不代表三个账号或权限角色。

第一阶段不建设登录、云同步、班级管理、多人数据、服务端数据库，也不扩充完整 3500 词。完整词库在学习机制稳定后单独实施。

## 信息架构

### 学习计划

- 首次打开为空白状态，引导用户创建计划或载入演示数据。
- 用户选择 List、开始日期和每天的新学数量后生成任务。
- 一个 List 完成初学后，系统在 Day+1、Day+2、Day+4、Day+7 安排复习。
- “今日任务”直接进入当前未完成步骤。
- 当天所有新学和复习任务完成后，系统自动打卡。

### 词表与学习流程

- 每个 List 必须打开自己的词数据，不能都指向 List 8。
- 用户可以把词标记为“需拼写”或“认识即可”。
- 单 List 学习顺序为：故事、回忆、词义测试、拼写测试。
- 只有“需拼写”的词进入拼写测试；全部词进入词义测试。
- 用户中途退出后，重新进入时从未完成步骤继续。

### 学习报告

报告页顶部只保留一组三视角切换和一个 List 范围筛选器。范围可选“全部”或某个 List；切换范围不会出现第二组三视角按钮。

- 学生视角回答：今天还要做什么、当前进度如何、哪些词需要加强。
- 家长视角回答：是否坚持学习、投入时间是否稳定、近期效果是否改善。
- 老师视角回答：哪些 List 和单词困难、识义与拼写差异如何、复习节奏是否合理。
- 选择单个 List 时，同一页面显示该 List 的成绩历史、薄弱词和复习次数。

三个视角必须读取同一份学习记录；不允许写死互相矛盾的数字。

## 数据模型

浏览器本地保存一个带版本号的学习档案，包含：

- 设置与当前模式（真实数据或演示数据）；
- 学习计划和每日任务；
- 每个 List 的步骤状态和掌握状态；
- 每次词义、拼写测试的逐题结果；
- 每个词的错误次数、连续正确次数和最近练习时间；
- 每日完成记录和有效学习时长。

所有页面只能通过统一的数据读写接口访问档案。初始化、读取失败、旧版本迁移和清空数据都有明确处理；损坏数据恢复为空白档案，同时给用户提示。

## 判定规则

- 完成故事和回忆步骤只代表已浏览，不代表掌握。
- 最近一次词义测试和拼写测试均达到 80%，且四个步骤全部完成，List 才标记为“本轮完成”。若该 List 没有需拼写词，则只要求词义测试达到 80%。
- 答错的词进入错题本并重置连续正确次数。
- 错题在后续有效测试中连续正确 3 次后移出错题本。
- 打卡由当天所有计划任务完成自动产生，不能用独立按钮跳过学习。
- 报告中的正确率按真实答题记录计算；没有记录时显示空状态，不显示模拟百分比。

## 演示模式

首次进入默认没有学习数据。用户可以主动载入一份独立的演示档案，界面持续显示“演示模式”。用户可退出演示并开始真实学习，演示数据不得覆盖真实档案。

## 代码结构

保留静态网站，不引入服务器。将当前大型 `index.html` 渐进拆分为：

- `index.html`：页面骨架和资源入口；
- `assets/styles.css`：视觉样式；
- `src/vocab-data.js`：现有演示词库；
- `src/store.js`：档案初始化、迁移、读取和保存；
- `src/scheduler.js`：计划与复习日期计算；
- `src/learning.js`：学习步骤、测试和掌握判定；
- `src/reports.js`：三视角指标计算；
- `src/app.js`：导航、渲染和事件连接。

业务计算函数不直接操作页面，以便独立验证。页面渲染读取计算结果，不自行保存另一份状态。

## 发布分支

当前 `main` 与线上使用的 `gh-pages` 已明显分叉。实施前先以线上 `gh-pages` 为功能基线，将后续源代码统一回 `main`，再由 GitHub Actions 从 `main` 发布 Pages。完成迁移后不再直接在 `gh-pages` 开发。

## 异常与数据安全

- 本地存储不可用时显示提示，允许当前会话临时使用。
- 日期、空计划、无拼写词和无测试记录均有清晰空状态。
- 清空真实学习数据必须二次确认。
- 导入或迁移的数据先验证结构和版本，不能直接作为页面内容执行。

## 验收标准

1. 新设备首次打开没有伪造学习成绩，并能载入与退出演示模式。
2. 创建计划后，刷新页面仍存在，今日任务与所选 List 一致。
3. 完成测试后，List 进度、错题本和三个报告视角同步变化。
4. 答错词进入错题本，连续三次答对后移出；刷新后状态不丢失。
5. Day+1、Day+2、Day+4、Day+7 复习任务按初学完成日期生成。
6. 总览和单 List 详情共用一组三视角入口，没有重复页面。
7. 所有 26 个 List 可打开各自的演示词数据，学习记录互不串联。
8. 手机宽度和桌面浏览器的核心流程均可操作，控制台无阻断错误。
9. `main` 的发布流程成功，线上页面内容与指定提交一致。
