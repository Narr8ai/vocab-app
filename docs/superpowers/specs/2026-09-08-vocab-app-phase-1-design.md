# Vocab App 产品设计与分阶段路线

## 目标

把现有 GitHub Pages 演示页改造成能够证明学习效率、提供可信学习证据，并可逐步发展为会员产品的词汇学习工具。

产品对四类参与者的承诺是：

- 学生：每天用较短时间记住更多词，并在一周后仍能回忆；
- 老师：能确认学生完成了有效测试和到期复习，并知道弱在哪里；
- 家长：能在 30 秒内判断孩子是否坚持、学习是否有效、是否需要帮助；
- 付费者：购买完整内容、持续效果、跨设备能力和省心服务，而不是为基础数据付费。

## 范围

第一阶段保留现有视觉风格、26 个 List 的产品结构和 GitHub Pages 在线访问方式。继续使用现有演示词库，先验证学习机制。保留学生、家长、老师三种报告视角，但它们只是同一用户数据的三种阅读方式，不代表三个账号或权限角色。

第一阶段不建设登录、云同步、班级管理、多人数据、服务端数据库，也不扩充完整 3500 词。完整词库在学习机制稳定后单独实施。

## 信息架构

### 学习计划

- 首次打开为空白状态，引导用户创建计划或载入演示数据。
- 用户选择 List、开始日期、每日可用时间和每天的新学数量后生成任务。
- 一个 List 完成初学后，系统在 Day+1、Day+2、Day+4、Day+7 安排复习。
- 到期复习优先于新学；逾期任务滚动重排，并受每日时间上限约束，不能把全部欠账一次压给学生。
- “今日任务”直接进入当前未完成步骤。
- 当天所有新学和复习任务完成后，系统自动打卡。

### 词表与学习流程

- 每个 List 必须打开自己的词数据，不能都指向 List 8。
- 用户可以把词标记为“需拼写”或“认识即可”。
- 单次新学控制在 5–8 个词，默认每日总学习时间约 10–15 分钟。
- 单 List 学习顺序为：短语境、主动回忆、词义测试、拼写测试。
- 短语境每组承载少量词，突出核心义、常用搭配和高考风格例句；允许学生跳过故事直接学习词条，以便后续比较效率。
- 主动回忆必须先让学生选择“会、模糊、不会”或作答，再展示答案；查看释义次数不计作掌握。
- 只有“需拼写”的词进入拼写测试；全部词进入词义测试。
- 词义测试采用有意义的同词性、近义或形近干扰项；答错后立即解释并在本轮末纠正一次。
- 拼写测试逐题反馈；词库为重要词提供默认拼写要求，学生调整后的记录仍保留用于效果分析。
- 用户中途退出后，重新进入时从未完成步骤继续。

### 学习报告

报告页顶部只保留一组三视角切换和一个 List 范围筛选器。范围可选“全部”或某个 List；切换范围不会出现第二组三视角按钮。

- 学生视角回答：今天还要做什么、当前进度如何、哪些词需要加强。
- 家长视角回答：本周是否按计划、复习后是否仍记得、当前是否需要介入、现在最合适的一个行动是什么。
- 老师视角回答：任务是否真实完成、哪些 List 和单词困难、识义与拼写差异如何、复习节奏是否合理。
- 选择单个 List 时，同一页面显示该 List 的成绩历史、薄弱词和复习次数。

三个视角必须读取同一份学习记录；不允许写死互相矛盾的数字。所有百分比标注统计周期和题目数量。没有足够数据时显示“暂无数据”或“数据不足”，不作能力判断。

第一阶段的家长和老师视角只供学生在当前设备上主动展示。页面明确说明数据仅存本机，不宣称远程监督、班级管理或云端同步。

## 数据模型

浏览器本地保存一个带版本号的学习档案，包含：

- 设置与当前模式（真实数据或演示数据）；
- 学习计划和每日任务；
- 每个 List 的步骤状态和掌握状态；
- 每次词义、拼写测试的逐题结果；
- 每个词的识义与拼写状态、错误次数、跨复习时点连续正确次数和最近练习时间；
- 每日完成记录和有效学习时长。

所有页面只能通过统一的数据读写接口访问档案。初始化、读取失败、旧版本迁移和清空数据都有明确处理；损坏数据恢复为空白档案，同时给用户提示。

## 判定规则

- 完成故事和回忆步骤只代表已浏览，不代表掌握。
- 最近一次词义测试和拼写测试均达到 80%，且四个步骤全部完成，List 才标记为“本轮完成”。若该 List 没有需拼写词，则只要求词义测试达到 80%。List 达标不覆盖仍未掌握的逐词状态。
- 答错的词进入错题本并重置连续正确次数。
- 错题必须在 3 个不同复习时点连续正确后移出当前错题队列；同一场内的纠正不增加跨时点连续正确次数。历史错误仍保留用于报告。
- 打卡由当天所有计划任务完成自动产生，不能用独立按钮跳过学习。
- 报告中的正确率按真实答题记录计算；没有记录时显示空状态，不显示模拟百分比。

## 演示模式

首次进入默认没有学习数据。用户可以主动载入一份独立的演示档案，界面持续显示“演示模式”。用户可退出演示并开始真实学习，演示数据不得覆盖真实档案。

## 代码结构

保留静态网站，不引入服务器。将当前大型 `index.html` 渐进拆分为：

- `index.html`：页面骨架和资源入口；
- `assets/styles.css`：视觉样式；
- `src/vocab-data.js`：现有演示词库；
- `src/store.js`：档案初始化、迁移、读取和保存；
- `src/scheduler.js`：计划与复习日期计算；
- `src/learning.js`：学习步骤、测试和掌握判定；
- `src/reports.js`：三视角指标计算；
- `src/app.js`：导航、渲染和事件连接。

业务计算函数不直接操作页面，以便独立验证。页面渲染读取计算结果，不自行保存另一份状态。

## 发布分支

当前 `main` 与线上使用的 `gh-pages` 已明显分叉。实施前先以线上 `gh-pages` 为功能基线，将后续源代码统一回 `main`，再由 GitHub Actions 从 `main` 发布 Pages。完成迁移后不再直接在 `gh-pages` 开发。

## 异常与数据安全

- 本地存储不可用时显示提示，允许当前会话临时使用。
- 日期、空计划、无拼写词和无测试记录均有清晰空状态。
- 清空真实学习数据必须二次确认。
- 导入或迁移的数据先验证结构和版本，不能直接作为页面内容执行。
- 计划名、词条和迁移数据以安全文本渲染，禁止未经处理写入可执行页面内容。
- 有效学习时长仅统计学习流程内的前台交互区间；切到后台、锁屏或长期无操作时暂停。

## 角色评审机制

每个阶段发布前执行六角色评审：

- 产品经理检查范围、用户价值、指标与商业边界；
- 学生检查每日负担、主动回忆、即时反馈和弃用风险；
- 老师检查任务、测试、复习和错词能否形成可追溯证据；
- 家长检查能否快速理解结果、提醒是否低压力且不过度监督；
- 开发检查数据模型、模块边界、迁移与发布安全；
- 测试用原始答题记录复算报告，并检查刷新恢复、跨 List 隔离、移动端和线上版本。

任何报告数字无法追溯、演示数据污染真实数据、不同 List 串联或刷新丢失核心记录，均阻断发布。

## 分阶段路线

### 阶段 0：版本与发布基线

将当前线上 `gh-pages` 功能安全迁回 `main`，保留发布工作流，记录迁移前线上版本并建立回滚点。后续只从 `main` 测试、构建和发布。同步修正 README 中不符合事实的“100% 闭环”等描述。

### 阶段 1：单设备真实学习 MVP

完成版本化本机档案、真实与演示隔离、计划和动态日期、26 List 数据隔离、断点续学、逐题记录、错题规则、复习调度、自动打卡、有效时长和统一三视角报告。

阶段目标是让系统从“可演示”变成“可测量”。

### 阶段 2：真实用户效果验证

用 2–4 周小规模试用验证学习效率和可信度。建议邀请 30–50 名学生，并记录个人原学习方式作为基线。核心指标：

- 北极星指标：D+7 仍答对的词数除以有效学习分钟；
- D+7 词义保持率和目标词拼写保持率；
- 每日实际时长、复习积压和计划完成率；
- 首日完成率、D7 与 D14 留存；
- 老师能否在 1 分钟内判断未完成项和薄弱点；
- 家长能否在 30 秒内判断坚持、效果、介入需要和下一步。

单位时间 D+7 记忆量相对个人基线提高 25% 作为内部试验目标，不在验证前作为营销承诺。

### 阶段 3：账号、家长端和老师端

效果验证达到预设门槛后，再建设账号、云同步、学生与家长双方同意的家庭绑定、老师布置任务、班级汇总、低频周报、异常提醒、数据导出、解绑和永久删除。

家长端遵循“少催一次、做对一次干预”：以周级趋势和可协商行动为主，不展示隐蔽监控、人格标签、同龄排名或考试分数预测。

### 阶段 4：会员商业化

免费版保留有限词库、基础学习流程、错题、基本进度和数据导出。会员提供完整且经校对的高考 3500 词、云同步、智能调度、家长独立账号、老师任务、长期趋势、阶段测评和高质量内容。

会员系统上线前必须明确试用、续费、取消、退款、到期后的数据访问，以及未成年人数据权限。登录、支付、远程通知和班级管理不进入第一阶段实现，但数据对象使用稳定 ID 和版本号，为未来迁移预留边界。

## 验收标准

1. 新设备首次打开没有伪造学习成绩，并能载入与退出演示模式。
2. 创建计划后，刷新页面仍存在，今日任务与所选 List 一致。
3. 完成测试后，List 进度、错题本和三个报告视角同步变化。
4. 答错词进入错题本，连续三次答对后移出；刷新后状态不丢失。
5. Day+1、Day+2、Day+4、Day+7 复习任务按初学完成日期生成。
6. 总览和单 List 详情共用一组三视角入口，没有重复页面。
7. 所有 26 个 List 可打开各自的演示词数据，学习记录互不串联。
8. 手机宽度和桌面浏览器的核心流程均可操作，控制台无阻断错误。
9. `main` 的发布流程成功，线上页面内容与指定提交一致。
10. 学生每天可以完成一个约 10–15 分钟的最小学习单元，逾期任务不会无限堆积。
11. 老师视角能从任务追溯到测试题目和结果；家长视角在 30 秒内给出事实、判断依据和一个建议行动。
12. 学习时长在页面后台或长期无操作时停止累计。

## 暂不实施

第一阶段不做完整词库、登录、云同步、真实家庭或师生绑定、支付、订阅、推送、排行榜、勋章皮肤、考试分数预测、复杂 AI 内容生成和大量装饰性图表。
